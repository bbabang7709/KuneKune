`CanvasEcho`는 원하는 Canvas에서 반복되는 텍스트 메아리를 재생하는 컴포넌트입니다. Inspector에서 `Target Canvas`와 `Excluded UI`를 지정하고 `Play()`를 호출합니다. 종료하려면 `Stop()`을 호출합니다. 화면의 네 방향에서 각각 5%를 제외하며, 기존 문구와 무작위 개수, 개별 유지 시간 및 소멸 시간은 유지합니다.

```csharp
[SerializeField] private CanvasEcho echo;

public void ShowEcho() => echo.Play();
public void HideEcho() => echo.Stop();
```

`Target Canvas`를 비우면 컴포넌트의 부모 Canvas를 찾습니다. `Echo Container`는 선택 사항이며, 비우면 지정한 Canvas 아래에 전용 레이어를 생성합니다. 직접 컨테이너를 지정할 때에는 해당 Canvas 안에 있는 RectTransform을 사용합니다. `Echo Text`에 기존 UI 텍스트나 텍스트 프리팹을 지정하면 글꼴과 크기를 복사합니다. 비워 두면 프로젝트의 NeoDunggeunmoPro 글꼴로 텍스트를 생성합니다. `Excluded UI`에는 가리지 않을 버튼, 패널 등의 RectTransform을 넣습니다. 빈 배열과 비어 있는 항목도 사용할 수 있습니다.

이번 변경의 설계는 **문제 재정의**와 **복잡성 분해**를 함께 적용했습니다. 핵심 요구는 메뉴에 종속된 연출을 다른 화면에서도 같은 방식으로 호출하는 것입니다. 기존 코드에는 화면을 어디에 그리는지 결정하는 처리와, 쿠네쿠네가 활성화된 메뉴에서만 재생할지 결정하는 처리가 함께 있었습니다. 이 두 책임을 구분하면 재사용하는 화면이 플레이어, 저장 관리자, 일시정지 메뉴에 접근할 필요가 없어집니다. 따라서 문제를 새로운 호러 연출을 만드는 작업으로 확대하지 않고, 이미 정해진 시각적 동작에 호출 대상과 배치 제외 영역을 명시하는 작업으로 정리했습니다. 색상, 문구, 등장 시간, 반복 간격을 함께 바꾸면 추출 자체의 결과를 확인하기 어려워지므로 기존 값을 이어받았습니다.

재사용 계층은 `CanvasEcho`가 담당하고, 기존 메뉴의 조건은 `PauseMenuEcho`가 담당합니다. 전자는 텍스트를 만들고, 사용할 위치를 고르고, 실제 시간을 기준으로 페이드와 이동을 진행합니다. 후자는 메뉴가 열렸는지, 플레이어의 열 수치가 쿠네쿠네 활성화 조건에 도달했는지, 저장 데이터를 불러오는 중인지 확인합니다. 다른 화면은 후자를 사용하지 않고 전자의 `Play()`를 직접 호출합니다. 기존 `PauseMenuUI`의 호출 경로를 유지하여, 메뉴에 연결된 다른 동작과 이번 추출을 함께 변경하지 않도록 했습니다. 프리팹에는 두 컴포넌트를 연결해 두었으므로 현재 메뉴의 사용 방식도 이어집니다.

공간 계산에서는 텍스트 중심만 안전한 위치에 있다고 해서 실제 글자가 안전하다고 판단하지 않습니다. 문구 길이에 따른 사각형 크기와 페이드 중 좌우 이동 범위를 함께 계산해 위치를 고릅니다. 화면 테두리에서 제외할 비율은 위아래뿐 아니라 좌우에도 같은 5%를 적용합니다. 텍스트 전체가 허용 영역 안에 들어갈 수 없는 경우에는 그 문구를 이번 반복에서 생략합니다. 제외 UI 주변에는 기존 16픽셀 여백을 유지하며, 같은 반복의 다른 메아리와도 겹치지 않는 위치를 찾습니다. 이런 제한은 무작위 개수보다 우선합니다. 요청된 개수를 채울 자리가 없을 때 버튼이나 패널을 가리는 결과를 만들지 않기 위해서입니다.

UI의 좌표는 Canvas마다 다를 수 있으므로, 제외 영역을 비교할 때에는 화면 좌표를 연결 지점으로 사용합니다. Overlay Canvas와 카메라를 사용하는 Canvas의 RectTransform은 동일한 월드 좌표만으로 비교하면 화면에서 보이는 위치와 차이가 날 수 있습니다. 각 UI의 Canvas 카메라를 통해 모서리를 화면 좌표로 옮기고, 필요한 경우 표시 컨테이너의 좌표로 다시 변환합니다. 재생 중 레이아웃이 이동하거나 크기가 바뀌는 경우에도 LateUpdate에서 현재 텍스트 영역을 검사합니다. 테두리나 제외 UI에 들어간 텍스트는 숨깁니다. 위치를 다시 뽑아 갑자기 다른 곳으로 옮기는 동작을 추가하지 않아 기존 연출의 흐름을 유지합니다.

시간과 생명주기도 별도로 유지합니다. 메뉴가 게임 시간을 멈추더라도 메아리가 진행되도록 실제 시간 기준의 대기와 프레임 시간을 사용합니다. 각 텍스트는 자신의 경과 시간과 유지 시간, 페이드아웃 시간을 갖습니다. 무작위 결과가 비슷해도 종료 시점이 겹치지 않도록 최소 0.15초 간격을 확보하는 기존 처리를 옮겼습니다. `Play()`를 다시 호출하면 이전 재생을 정리하고 새 반복을 시작하며, `Stop()`은 반복과 표시 중인 텍스트를 함께 정리합니다. 생성한 텍스트는 반복마다 새로 만들지 않고 재사용합니다. 비활성화할 때에도 정리하도록 하여, 화면을 닫은 뒤 텍스트가 별도 Canvas에 남는 일을 줄입니다. 이러한 구조는 시각적 결과를 유지하면서 호출 장소만 확장하는 데 목적이 있습니다.

다음 열 가지는 동일한 컴포넌트를 재사용하는 적용 아이디어입니다. 새로운 게임 규칙을 자동으로 추가한 것은 아니며, 각 화면의 기존 이벤트에서 `Play()`와 `Stop()`을 연결하는 방식입니다.

1. **일시정지 메뉴의 기존 역할 유지.** 현재 메뉴는 이미 연결되어 있습니다. 메뉴 배경의 CanvasEcho는 화면 전체를 후보로 삼고, 세 버튼의 RectTransform을 제외합니다. PauseMenuEcho가 쿠네쿠네 활성화 조건을 확인하므로 일반 상태의 메뉴에는 기존처럼 메아리를 재생하지 않습니다. 이 화면을 기준 사례로 두면 다른 화면에 연결한 결과를 비교하기 쉽습니다. 문구, 색, 글꼴, 반복 간격을 먼저 동일하게 두고 제외 영역만 바꾸면, 화면마다 달라지는 부분이 배치 조건이라는 점도 명확해집니다. 메뉴를 닫거나 확인창을 열 때 호출하는 Stop도 그대로 사용할 수 있습니다.

2. **인벤토리의 정보 읽기 공간 보호.** 인벤토리 화면에서는 슬롯 격자, 선택한 물건의 설명 패널, 닫기 버튼을 제외 UI로 지정할 수 있습니다. 격자의 모든 슬롯을 하나씩 등록하는 대신 슬롯들의 부모 패널 RectTransform을 넣으면 격자 전체를 보호할 수 있습니다. 비어 있는 배경에는 동일한 메아리가 반복되지만, 아이템 이름과 설명을 읽는 영역은 배치 후보에서 빠집니다. 인벤토리를 여는 기존 이벤트에서 Play를 호출하고 닫는 이벤트에서 Stop을 호출하면 됩니다. 열 수치 같은 조건이 필요하면 인벤토리 쪽 코드가 결정하며, 메아리 컴포넌트에 조건을 추가할 필요는 없습니다.

3. **대화창 주변의 빈 공간 사용.** 대화 화면에서는 대사 패널과 선택지 패널을 제외 목록에 넣어 메아리가 문장을 덮지 않도록 할 수 있습니다. 캐릭터 이름이나 얼굴 이미지도 읽기 흐름에 영향을 주는 경우에는 그 영역을 함께 등록합니다. 같은 연출을 사용하더라도 중요한 대사를 침범하지 않으면 플레이어는 대화와 배경의 불편한 생각을 구분해서 볼 수 있습니다. 선택지의 높이나 위치가 대화마다 달라지는 경우에도 현재 RectTransform을 검사하는 방식을 이용합니다. 대화가 끝났을 때 Stop을 호출하면 다음 장면에 메아리가 이어지는 것을 정리할 수 있습니다.

4. **일기와 기록 화면에서 본문 보호.** 일기 UI에는 긴 본문이나 스크롤 영역이 있을 수 있으므로, 본문을 담은 패널 전체를 제외하는 방식이 적합합니다. 페이지 이동 버튼과 닫기 버튼도 필요에 따라 추가합니다. 그러면 기록의 내용은 읽을 수 있고, 문서 주변에 남아 있는 배경에서 기존 메아리가 나타납니다. 본문 글꼴을 Echo Text 템플릿으로 사용할 수도 있지만, 현재 메뉴와 같은 인상을 유지하려면 기존 메아리 텍스트를 템플릿으로 지정합니다. 기록을 넘길 때마다 Play를 다시 호출할지는 해당 화면이 결정하며, 호출하면 이전 표시를 정리한 뒤 새 반복을 시작합니다.

5. **지도 화면의 범례와 조작 버튼 보호.** 지도에 메아리를 연결할 때에는 범례, 확대·축소 버튼, 지역 정보 패널을 제외할 수 있습니다. 지도 전체를 제외하면 남는 후보가 거의 없으므로, 실제로 읽어야 하는 UI 범위를 기준으로 등록하는 것이 필요합니다. 지도 위에 텍스트가 나타나도 되는 기획이라면 중요 패널만 보호하고 기존 무작위 배치를 사용합니다. 반대로 지도 자체도 보호해야 한다면 지도 RectTransform까지 제외하면 됩니다. 안전한 공간이 부족한 반복에는 표시 개수가 줄어들 수 있으며, 이때 제외 영역을 무시해 강제로 텍스트를 배치하지 않습니다.

6. **상호작용 확인창의 선택 영역 보호.** 문을 열거나 특정 물건을 조사할 때 사용하는 확인창에도 재사용할 수 있습니다. 확인 문구와 확인·취소 버튼을 담은 부모 패널을 제외 목록에 넣으면 창 전체를 보호합니다. 뒤쪽 배경에는 같은 색상과 페이드로 메아리를 반복하여, 선택을 해야 하는 화면에 이미 사용 중인 분위기를 이어갈 수 있습니다. 확인창을 열 때 Play를 호출하고 어느 선택으로 닫히든 Stop을 호출하도록 연결하면 호출 흐름도 단순합니다. 연출을 특정 선택에 반응하도록 만드는 기능은 추가하지 않았으므로, 기존 무작위 반복이라는 규칙은 유지됩니다.

7. **별도 컷신 Canvas에 독립적으로 연결.** 컷신 전용 Canvas가 있다면 그 Canvas를 Target Canvas로 지정하고, 자막 영역과 건너뛰기 버튼을 제외할 수 있습니다. 컴포넌트를 메뉴 객체 아래에 둘 필요가 없으므로 컷신을 담당하는 객체에 배치할 수 있습니다. 컷신 시작 이벤트에서 Play를 호출하고 종료 또는 건너뛰기 이벤트에서 Stop을 호출하면 됩니다. 메아리는 실제 시간을 사용하므로 컷신의 게임 시간 설정과 별도로 진행됩니다. 이 동작을 사용할지 여부는 컷신의 기존 코드가 결정해야 하며, CanvasEcho 자체가 컷신 관리자에 접근하거나 자동 구독하지는 않습니다.

8. **HUD와 다른 Canvas의 UI도 함께 보호.** 메아리를 표시하는 Canvas와 상태 정보를 표시하는 Canvas가 다를 때에는 HUD의 체력 표시, 조작 안내, 목표 패널 등의 RectTransform을 그대로 제외 목록에 넣을 수 있습니다. 화면 좌표를 사용해 비교하므로 서로 다른 Canvas에서 보이는 위치를 기준으로 영역을 피하도록 구성했습니다. 표시용 Canvas를 바꾸기 위해 HUD 구조를 옮길 필요는 없습니다. 다만 실제 화면에서 사용하는 카메라와 Canvas 설정은 각 UI에 올바르게 연결되어 있어야 합니다. 설정만으로 보호할 UI를 늘릴 수 있어, 새로운 화면마다 메아리 배치 코드를 복사하는 일을 줄입니다.

9. **설정 화면의 조작 공간 보호.** 설정 화면에서는 슬라이더, 드롭다운, 적용 버튼을 포함하는 패널을 제외할 수 있습니다. 설정 UI의 항목이 늘어날 때에도 패널을 기준으로 보호하면 개별 항목을 모두 다시 등록하지 않아도 됩니다. 메아리 텍스트에는 raycastTarget을 끄므로 생성된 글자가 클릭을 받는 용도로 동작하지 않습니다. 배치에서도 설정 패널을 피하도록 지정하면 조작 중 가독성을 유지할 수 있습니다. 이 활용은 기존 연출을 설정 화면에 연결할 수 있다는 예시이며, 현재 설정 화면에서 자동으로 메아리를 재생하도록 변경한 것은 아닙니다.

10. **재사용 화면 프리팹으로 설정 전달.** 여러 화면에서 같은 문구와 글꼴을 사용할 경우, CanvasEcho가 들어 있는 화면 프리팹을 복제하고 Target Canvas 및 제외 UI 참조만 각 화면에 맞게 설정할 수 있습니다. 기존 UI 텍스트를 Echo Text에 지정하면 그 스타일을 복사하므로 별도의 폰트 처리 코드를 만들 필요가 없습니다. Play와 Stop이라는 호출 형태도 모든 화면에서 같게 유지됩니다. 화면별로 필요한 게임 조건은 호출하는 쪽에 두고, 메아리 컴포넌트는 표시와 배치만 담당하게 구성하면 향후 오류를 확인할 범위도 작아집니다. 생성 레이어가 자동으로 만들어지는 구성을 쓰면 컨테이너를 매번 수동으로 준비하지 않아도 됩니다.
